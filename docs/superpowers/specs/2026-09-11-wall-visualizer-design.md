# Визуализатор шпалер «Подивитись в інтер'єрі» — дизайн

Дата: 2026-09-11. Статус: одобрен владельцем («делай сразу A, пресетные комнаты»,
фото комнат — бесплатные стоковые). Путь: архитектурный (новая клиентская
подсистема PDP).

## 1. Цель

Покупатель шпалер боится «как это будет у меня дома». На PDP каждой wc-*
позиции с фото появляется блок «Подивитись в інтер'єрі»: модалка с фото
комнаты-пресета, где выбранная шпалера «наклеена» на стену. Покупатель
двигает угловые ручки стены под своё помещение, задаёт высоту стены —
видит шпалеру в перспективе и число смуг для этой стены.

## 2. UX-флоу

1. PDP (wc-*, есть главное фото): блок-кнопка под галереей.
2. Открытие: fullscreen-модалка на мобильном, крупная центрированная —
   на десктопе (`sm:`). Внутри: фото комнаты; на стене — текстура шпалеры;
   4 угловые ручки (pointer events, тап-зоны ≥44px, клавиатурные стрелки
   шагом 0.01 нормализованных координат).
3. Слайдер «Висота стіни» 2.0–3.5 м (шаг 0.05, дефолт 2.7).
4. Футер модалки: «≈ N смуг для цієї стіни» + кнопка «До калькулятора»
   (закрывает модалку и скроллит к RollCalculator; автоподстановка высоты
   — v2). Кнопка «Скинути» — дефолтный quad пресета.
5. Выбор комнаты: 4 миниатюры пресетов.
6. Подгонка quad сохраняется в localStorage per (room, product slug).
7. Esc/крестик закрывают, фокус возвращается на кнопку открытия.

## 3. Архитектура — три узла

### 3.1 `app/lib/wallpapers/visualizer-math.ts` (pure, node:test)

- `matrix3dForQuad(quad, size)` — гомография, отображающая углы элемента
  `(0,0),(w,0),(w,h),(0,h)` в quad. Quad приходит в ПИКСЕЛЯХ бокса фото
  (компонент переводит нормализованные 0..1 пресета через фактические
  размеры `<img>` — так пропорции не искажаются на непрямоугольных фото).
  Решение системы 4 соответствий (8 неизвестных); возвращает CSS-строку
  `matrix3d(...)` или `null` для вырожденного quad (det ≈ 0).
- `clipPathForQuad(quad)` — строка `polygon(...)` в пикселях бокса.
- `wallWidthM(quad, wallHeightM)` — средняя ширина quad / средняя высота
  quad (в пикселях) × wallHeightM: высота известна от слайдера, ширина
  выводится по пропорции проецируемой стены.
- `stripsForWall(wallWidthM, rollWidthCm)` — `ceil(w / (cm/100))`.
  Финальная покупная математика остаётся в roll-math/калькуляторе.

Техника наложения (обходит CORS хотлинков Славы — канвас не используется):
wrapper-слой поверх фото комнаты с `clip-path` по quad; внутри — div с
`background-image: url(текстура); background-repeat: repeat;
background-size: (полоса = rollWidthCm см в масштабе стены)` и
`transform: matrix3d(...)`. Клип родителя режет уже трансформированный
рендер потомка.

### 3.2 `app/components/WallVisualizer.tsx` ('use client')

- Props: `{ textureUrl: string; rollSize: RollSize | null; slug: string }`.
  `rollSize === null` → тайлинг 0.53 м и подсказка «розмір рулона не
  вказано — масштаб орієнтовний».
- Подключение из PDP через `next/dynamic` с `ssr: false` (не попадает в
  серверный бандл/гидратацию).
- Состояние: комната, quad, высота стены. localStorage-ключ
  `wallviz:{slug}:{roomId}`.
- Полосатость тайлинга: ширина полосы на экране = widthCm / (wallHeightM м)
  пропорционально высоте стены на фото (высота стены задаётся слайдером и
  соответствует текущей высоте quad — ручки меняют пропорции, слайдер —
  физический масштаб).

### 3.3 Пресеты комнат

- `/public/rooms/{vitalnia,spalnia,dytiacha,kukhnia}.webp` — 1600px по
  ширине, ≤400KB, пустые комнаты с чистой стеной; источники — Unsplash/
  Pexels (лицензии допускают коммерческое использование), атрибуция и
  ссылки — `/public/rooms/CREDITS.md`. Фото утверждаются владельцем до
  вшивания.
- `/public/rooms/rooms.json`: `[{ id, src, label, wall: [[x,y]×4],
  wallHeightM }]` — дефолтный quad и высота по факту фото.

## 4. Доступность и мобильный

Ручки: `<button aria-label>`, ≥44×44, `touch-action: none` на ручках
(страница не скроллится при драге), pointer capture. Модалка: `role=dialog`,
aria-modal, Esc, фокус-трап простой (Tab по кругу), возврат фокуса.
`motion-reduce:transition-none` на анимациях. Тексты ≥16px (наш мобильный
контракт), `wrap-anywhere` на подписях.

## 5. Производительность

Комнатные фото и текстура грузятся только при открытии модалки (dynamic
import + `loading` состояний). Матрица/clip пересчитываются в
`useMemo` по quad. Никаких обращений к БД.

## 6. Edge cases

- Нет фото/текстуры → блок на PDP не рендерится.
- `rollSize = null` → 0.53 м + предупреждение (не вгадываем — контракт
  калькулятора).
- Ручки clamp в 0..1 и запрет вырождения (минимальная площадь quad —
  Math.round защита в math-слое возвращает null, UI не даёт довести).
- Отказ localStorage (private mode) → молча без сохранения.

## 7. Тесты

- `tests/wall-visualizer-math.test.ts`: гомография roundtrip (углы
  элемента → quad в пределах ε), вырожденный quad → null, clip-path строка,
  stripsForWall (граничные), миграция единиц см/м.
- `tests/wall-visualizer.test.ts` (статические инварианты, обычай проекта):
  dynamic ssr:false, тап-зоны ≥44, pointer capture, localStorage-ключ,
  наличие Esc и кнопки «Скинути», PDP-гейт (только wc-* с фото),
  `touch-action: none` на ручках.

## 8. Вне скоупа v1 (YAGNI)

Загрузка своего фото, AR, экспорт/шеринг картинки (нужен html2canvas),
учёт раппорта узора (ровный тайлинг), автоподстановка высоты в
калькулятор (кнопка-скролл только), выбор стены в комнате (одна стена).

## 9. Риски

- Лицензии стоков — только Unsplash/Pexels + CREDITS.md.
- Швы тайлинга на некоторых сканах текстур — приемлемо (v1), раппорт — v2.
- Разные пропорции комнат — quad нормализован 0..1, rooms.json задаёт
  дефолты per фото.
