# Дизайн: категория «Шпалери» — импорт из 1С 7.7 + фото + ежедневный sync

Дата: 2026-09-10 · Статус: на рассмотрении владельца
Решения владельца учтены: категории = 10 подгрупп магазина; цена = розничная из 1С;
sync ежедневно в 14:00; Telegram-бот списания ОТМЕНЁН (правда наличия = дневной sync).

## 1. Цель

Выставить на витрину обои из стока магазина (534 SKU, 4637 рулонов,
инвентаризация 10.09) с автоматическим ежедневным обновлением цен/остатков
из 1С 7.7 («Производство + Услуги + Бухгалтерия», укр.) на отдельном ПК
владельца (Windows 10 Корпоративная), и добрать фото из открытых источников.

## 2. Источники данных

| Данные | Источник | Способ |
|---|---|---|
| Номенклатура, розничная цена, остаток | 1С 7.7 владельца | VBS-скрипт (черновик: `scripts/1c-export/`) → POST на ingest-endpoint |
| Фото, приоритет 1 | oboi-slav-oboi.com | хотлинк (уже проверен: HTTP 200, без referer), матч по артикулу в slug |
| Фото, приоритет 2 | epicentrk.ua, shpalery-ua.com, styleo.com.ua, shpaleru.com.ua | скачать КОПИИ в наш Storage (чужие витрины хотлинкать не надёжно), матч по полному артикул-токену |
| Фото, хвост ~236 позиций | вручную | запрос фото у поставщиков или своя съёмка (чек-лист по ценности остатков); фаза 2 |

Покрытие фото автоматикой (проверено живыми пробами 2026-09-10):
198 (Слав) + ~100 (4 доп. источника, из них 24 дублируются между собой —
перекрёстная валидация) ≈ **298 из 534 (56%)**.

## 3. Канал данных (ежедневный)

1. Планировщик Windows, ежедневно 14:00 (пропущенный запуск догоняется при
   включении ПК): `cscript.exe` (32-bit) → OLE `V77.Application` → только-чтение
   → CSV `code;name;article;unit;price_retail;qty` (UTF-8, `;`) →
   `MSXML2.ServerXMLHTTP` POST на `https://towary-dla-domu.com/api/ingest/1c-wallpaper`
   c `Authorization: Bearer <ключ>` + заголовки `X-Export-Date`, `X-Row-Count`.
2. Ingest-endpoint (`app/api/ingest/1c-wallpaper/route.ts`, maxDuration 60):
   проверка ключа constant-time (модель cron-роута), санитайзер CSV,
   запись в staging-таблицу `wallpaper_stock` (новая, RLS on, без policies —
   только service role, по образцу `yc_content_goods`), ответ `202 {rows}`.
   Локальная копия CSV остаётся на ПК владельца (резерв).
3. Импортер (CLI, по образцу Юга: `--plan` dry-run / `--run` батчами,
   идемпотентный, чекпоинты):
   - парсинг названий: артикул в 3 форматах (`NNNN-NN`, `NNNNN`, `NNNN NN`);
     размер рулона из названия (`53см*10м`, `0,53*10м`, `рулон 53см*10м`...);
   - категории: 10 подгрупп отчёта → категории сайта (укр. названия:
     Акрил, Вініл 10 м, Вініл 15 м, Дуплекс, Метрові, Флізелін, Шовкографія,
     Мійка проста, Прості шпалери, Супермійка). Ствол — категория «Шпалери»;
   - цены: ТОЛЬКО розничная из файла; хук-множитель наценки в конфиге
     (по умолчанию 1 — решение владельца);
   - товары: slug из артикула; дубли размеров (один дизайн в 53×10/53×15/106×10)
     — если в файле отдельные строки с собственным кодом → отдельные товары
     (финальное решение после повторной инвентаризации);
   - позиции, исчезнувшие из файла → OOS (паттерн mark-missing-oos), не удаление;
   - остаток 0 → «Немає в наявності» (см. §5).

## 4. Фото-пайплайн (CLI, idempotent)

1. Индекс Слава (sitemap-product-ua.xml, 6336 URL) → матч `NNNN-NN` в slug →
   главный `assets/products/<id>/*.jpg` + до 12 текстур → хотлинк-URL в
   `product_images` (external passthrough).
2. Индексы доп. источников (sitemaps Epicentr/shpalery-ua/styleo/shpaleru —
   все открыты, у Horoshop-пар лёгкий PoW-обход cookie) → матч ПОЛНОГО
   артикул-токена (строгий, не базовое число — иначе ложные совпадения) →
   скачать копию → upload в Supabase Storage `product_images` → относительный
   путь в БД. Дубли между источниками: первый по приоритету, остальные —
   альтернативы (не пишем).
3. Не найденные → отчёт «чек-лист фото» (сортировка по ценности остатка
   qty×price) для ручной съёмки/запроса поставщикам.
4. Публикация витрины только позиций с ≥1 фото (действующий eligibility-
   контракт не меняем); позиции без фото импортируются is_active=false и
   ждут фото.

## 5. Правило наличия (миграция 040)

Триггер на `products`/`product_variants`: `stock_quantity = 0` →
`availability_status = 'out_of_stock'`, `> 0` → `'in_stock'`.
Цель: честный флаг на витрине при любых списаниях (синк 1С, продажи с сайта,
ручные правки). Юг-синк не ломается (пишет оба поля согласованно).
Place_order не изменяется. Pre/post VERIFY-SELECT'ы в шапке миграции;
применение — через MCP по поручению владельца. **Формально ещё не
подтверждено владельцем — GO-пункт.**

## 6. Мониторинг и контроль

- Ожидаемость файла ежедневно: freshness-проверка staging (`max(export_date)`;
  нет файла > 26ч → уведомление владельцу (Telegram-канал уведомлений уже есть).
- Первые 2 недели: ежедневная контрольная сводка «принято N строк, обновлено
  цен M, остатков K, новых X, исчезло Y» владельцу.
- Sanity: ожидаемый объём ~534±50 строк; цена 50..5000 грн; qty 0..999 —
  за пределами → warning и reject строки (не всего файла).

## 7. Фаза 2 (после запуска витрины)

- Калькулятор рулонов на PDP (периметр/высота + «з підбором/без»,
  размеры рулона уже в данных) + кнопка «Додати N у кошик».
- Фото-хвост: чек-лист → съёмка/запрос поставщикам → добор в пайплайн.

## 8. Инварианты и безопасность

- money-path (place_order/applyPaid/callback) не затрагивается.
- Ключ выгрузки: env Vercel + локально у владельца; constant-time проверка;
  ротация = смена env. Никогда в репо/чатах.
- Секреты 1С (логин/пароль выгрузки) — только на ПК владельца в VBS; в
  репо — плейсхолдеры. Рекомендован отдельный пользователь 1С только-чтение
  (админский допустим, но не рекомендуется).
- staging и ingest — service-role only (RLS on, policies нет).
- Коммит/пуш всего батча — одной пачкой по GO владельца; каждый коммит атомарный.
