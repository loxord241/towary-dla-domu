# Пропозиція: шаблон опису товару за зразком Epicentr (epicentrk.ua)

Дата: 2026-09-14 · Статус: на рассмотрении владельца
Дослідження: 3 живі картки epicentrk.ua (посуд, побутова техніка, шпалери),
зняті 2026-09-14; дані нашої БД — запити до `products` (5374 SKU, 5280 активних).

## 1. Цель

Вирівняти картки товару towary-dla-domu.com за структурою великих українських
маркетплейсів: лід-абзац + «основні характеристики» + таблиця характеристик.
Мета — закрити ~34% активних товарів взагалі без тексту опису і замінити
брендовий бойлерплейт постачальників на нейтральний фактичний текст.

## 2. Как устроены карточки Epicentr (исследование)

Просмотрено 3 карточки разных категорий:

- Посуда: «Набор сковородок WMF 3 шт.» (epicentrk.ua/shop/mplc-nabir-skovoridok-z-antiprigarnim-pokrittam-wmf-3-st-…​.html)
- Бытовая техника: «Электрочайник Edenberg EB-83552» (epicentrk.ua/shop/mplc-elektrocajnik-edenberg-eb-83552-…​.html)
- Обои: «Обои A.S. Creation New wall 37489-3» (epicentrk.ua/shop/oboi-a-s-creation-new-wall-37489-3.html)

### 2.1 Порядок блоков (единый для всех категорий)

| № | Блок | Объём | Примечание |
|---|---|---|---|
| 1 | H1 — название + код товара + наличие | 1 строка | артикул в скобках в H1 |
| 2 | Цена + CTA «Купить» | — | повторяется внизу карточки |
| 3 | «Основные характеристики» | 3–5 строк | выжимка: Тип, Материал, Диаметр / Мощность + ссылка «Все характеристики» |

| 5 | «Характеристики» — полная таблица | 11–25 строк | главный информационный блок; пары «название–значение», иногда с подгруппами |
| 6 | Фото-галерея | — | |
| 7 | Отзывы/вопросы | — | рейтинг + список |
| 8 | SEO-блок «Популярные запросы» | ~10 ссылок | |

Чего у Эпицентра НЕТ: отдельной «Комплектации», блока «Преимущества» списком,
FAQ. Доставка — только бейдж у цены, не текстовый блок.

### 2.2 Ключевые наблюдения по категориям

- **Посуда/техника**: описание — короткий фактический абзац (WMF: ~70 слов —
  материал, покрытие TransTherm®, индукция) или маркированный список фич
  (чайник Edenberg: ~10 пунктов). Никакой «воды» про бренд.
- **Обои**: текстового описания НЕТ ВООБЩЕ — карточка держится на таблице
  характеристик (23 строки: основа, тип, раппорт 64/32, ширина/длина рулона,
  комната, уход) + дисклеймер об оттенке (~40 слов) + выбор модели-размера.
- Характеристики везде отдельной таблицей, порядок строк = порядок в фиде
  поставщика, без нормализации ключей между поставщиками (у Эпицентра тоже).
- Заголовки разделов — h2 над КАЖДЫМ блоком («Описание …», «Характеристики …»),
  внутри текста описания подзаголовков нет.

## 3. Что у нас уже есть на PDP (не дублируем, используем)

- Таблица характеристик: `app/components/ProductSpecifications.tsx` рендерит
  `products.specifications` (jsonb `[{name,value}]`) — section- и inline-вариант.
- Описание: `app/lib/product-description.ts` — sanitizer + placeholder-детекция,
  fallback description → short_description → «Опис відсутній».
- Отзывы, похожие товары, RollCalculator (обои), JSON-LD Product, breadcrumbs.
- Чего нет: блока «Основні характеристики» (top-3…5 выжимка), лид-абзаца,
  сгенерированного текста когда `description` пустой (сейчас — заглушка).

## 5. Шаблон описания (предложение)

Порядок на PDP — как у Эпицентра:

```
H1 {name} ({sku})
Лид-абзац (генерация, 2–4 предложения, ≤60 слов):
  «{Тип} {brand} {Серія} — {ключевой факт 1}, {ключевой факт 2}.
   {ключевой факт 3}.»
  — только факты из specifications/name/brand, ноль оценочных суждений.
Основні характеристики (новый блок): до 5 строк из specifications
  по словарю приоритетных ключей категории
  (посуда: Тип→Матеріал→Діаметр→Антипригарне покриття→Тип джерела тепла;
  техника: Тип→Потужність→Об'єм→Матеріал корпусу→Оснащення;
  шпалери: Тип→Основа→Розмір рулону→Мийність→Країна).
Опис: supplier `description` (уже санитизирован) ЕСЛИ не placeholder;
  ИНАЧЕ сгенерированный текст из specifications (маркированный список фич —
  формат Эпицентра для техники, абзац — для посуды).
Характеристики товару: ProductSpecifications (уже есть, без изменений).
Отдача/оплата, отзывы, похожие — существующие блоки.
```

Правила генерации лида: (1) только строки из `specifications`, `brand`, `name`,
`price`; (2) единицы измерения из значений фида не менять; (3) язык — украинский;
(4) значение «Немає»/«Так»/«Ні» переформулировать («без кришки», «з антипригарним
покриттям»), не копировать «Так/Ні» в текст; (5) длина 2–4 предложения.

## 8. Риски

1. **Шаблонность/SEO**: единый каркас → тысячи похожих лидов. Митигируется
   вариативностью формул по категориям и тем, что лид короткий (основной
   контент — уникальная таблица характеристик + отзывы).
2. **Бойлерплейт поставщика**: у 65% товаров текст — рекламный бланк бренда
   («втілені останні інноваційні досягнення…»), тот же текст у сотен магазинов.
   Перезапись улучшает уникальность, но теряется «маркетинговый» тон — вопрос
   вкуса владельца.
3. **Ключи specifications не нормализованы** между поставщиками Юга
   («Тип джерела тепла» / «Тип» / «Призначення») — нужен словарь приоритетных
   ключей per-категорию и фолбэк «первые N строк».
4. **Правдивость**: генерация ТОЛЬКО из фактов фида; при отсутствии ключа —
   предложение просто не пишется. Никаких «преимуществ» и гарантий извне.
5. **Одобрение владельца**: перезапись существующих текстов без согласования —
   риск; изменённые тексты не должны публиковаться мимо владельца.

**Генерировать автоматически в черновики + батчевое утверждение владельцем.**
Не публиковать сразу:

1. Фаза 1 (без риска): новый PDP-блок «Основні характеристики» — чистый рендер
   существующего `specifications` по словарю приоритета, ничего не утверждаем,
   контент уже публичен в таблице ниже по карточке.
2. Фаза 2: CLI-генератор (паттерн `scripts/yugcontract-import.ts`:
   `--plan` dry-run / `--run`) пишет лид+описание в staging (по образцу
   `yc_content_goods`), НЕ трогая `products.description`. Владелец
   просматривает батчи по категориям и утверждает.
3. Очерёдность: сначала 1339 товаров без описания (максимальный прирост,
   владелец сравнивает «была заглушка → стал полный текст»), затем — точечная
   перезапись бойлерплейта по решению владельца.
