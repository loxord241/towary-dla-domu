## 1. Executive Summary

Состояние: **инженерно SEO-база выдающаяся** (canonical/noindex-политика с инвариантом
«индексируемое = sitemap», честный JSON-LD, ISR-архитектура, чистые URL категорий с 308-ми,
merchant-фид), но **сайт практически невидим в Google**, потому что ему 3 недели от роду и
у него нет измеримого контура наблюдаемости.

Три главных блокера:

1. **Каталог создан 2026-08-24…2026-09-15 (FACT, БД)** — весь сайт для Google новый; ждать
   органики «по умолчанию» нельзя, нужен управляемый цикл: GSC → индексация → сниппеты →
   итерации.
2. **Vercel Attack Mode включён (FACT)** — каждый URL (включая /robots.txt и /sitemap.xml)
   отвечает 429 + `x-vercel-mitigated: challenge` любому неверифицированному клиенту, на
   обоих доменах, с любым UA. Вербифицированный Googlebot по докам Vercel пропускается
   автоматически (INFERENCE — проверить по Firewall Observability), но Bing-класс краулеров,
   мессенджер-превью, SEO-инструменты и аудит-краулеры отсечены. Ущерб Google-индексации —
   UNKNOWN; потолок риска — полный отсев.
3. **Search Console недоступна (UNKNOWN)** — нет ни одного числового показателя
   показы/клик/позиция. Все CTR/позиционные разделы этого отчёта качественные.

Главные quick wins: получить доступ к GSC и отправить sitemap; решить вопрос Attack Mode;
убрать дубль title «Шпалеры» (/oboi ↔ /catalog/shpaleri); переписать title/description
главной; чинить грамматику шаблона title категорий; сжать 1 934 переливающих PDP-title.

Самая сильная возможность роста: **точные модельные запросы** («праска tefal fv2c41e0») —
4 897 PDP с точными слагами-моделями, в выдаче по таким запросам уже ранжируются
микро-магазины (SERP-наблюдение), а наши title обрезаются.

## 3. Critical Findings

### C1. Vercel Attack Mode включён — весь сайт 429/challenge для неверифицированных клиентов — FACT
- `curl -I https://towary-dla-domu.com/{,/robots.txt,/sitemap.xml,/catalog}` → **429**,
  `server: Vercel`, `x-vercel-mitigated: challenge`, HTML «Vercel Security Checkpoint».
  То же с UA Googlebot, то же на `towary-dla-domu.vercel.app`.
- Доки Vercel (обновлены 2026-08-11): «Attack Mode automatically recognizes and allows
  [known bots] … Search engine crawlers like Googlebot are automatically allowed through …
  will not negatively impact your site's SEO». Верификация ботов — по IP/поведению, не по UA.
- **Googlebot скорее всего проходит** (INFERENCE, высокая уверенность). Но: превью в
  Telegram/Viber/соцсетях, Bing-класс боты (в директории, но не гарантировано), price-
  агрегаторы, Wayback и весь SEO-инструментарий получают 429. Дата включения UNKNOWN —
  проверить Vercel Firewall Observability.
- Действие: владельцу проверить дату/причину включения в Vercel dashboard; если активной
  атаки нет — выключить или заменить на адресные WAF-правила. Это настройка Vercel, не код.

### C2. Сайт-«новорождённый»: весь каталог создан за 3 недели — FACT (БД)
- oldest created 2026-08-24, newest 2026-09-15; eligible 5 021; created_30d = 100%.
- Следствие: без GSC-базлайна и ручной подачи sitemap органика не стартует управляемо.
  Google уже видел часть legacy-URL `?category=` (см. §7) — сейчас они 308-ят на новые пути.

### C3. Search Console недоступна — UNKNOWN (по правилам брифа §51)
- Все числовые CTR/позиции/индексация = UNKNOWN. Разделы 5–6 отчёта качественные.

### C4. Soft-404 регрессия: loading.tsx превращает «настоящие 404» в 200+noindex — FACT (код/доки), live-статус не проверен
- `app/product/[slug]/loading.tsx` и `app/oboi/loading.tsx` (2026-09-13), `app/catalog/loading.tsx`
  (2026-08-23) существуют; tests/perf-package.test.ts их фиксирует.
- Next 16 docs (loading.md §Status Codes): при стриминге «a 200 status code will be returned…
  the status code cannot be updated» → notFound() в PDP/категории после начала стрима = 200.
- Митигация подтверждена: runtime инжектит `<meta name="robots" content="noindex">` в
  not-found boundary (node_modules/.../http-access-fallback/error-boundary.js:83) — индексного
  блума нет, но GSC получит «noindex»/soft-404 вместо чистых 404, а комментарии в коде
  («must be a real HTTP 404») теперь неверны. Противоречит контракту design-doc от 2026-08-26.
- Решение требует design-решения (см. §19, R13): вернуть true-404 (убрать/перенести
  loading-границы) ИЛИ легализовать 200+noindex и поправить документацию. UX-ценность
  скелетонов была причиной их введения — нетривиальный трейд-офф.

### C5. Self-каннибализация «Шпалеры»: /oboi ↔ /catalog/shpaleri — FACT (title), эффект INFERENCE
- Обе страницы индексируемые, canonical на себя. Title **идентичен**: «Шпалери — купити в
  Товари для дому» (seo.ts:262 vs 212). Product-set: 444 wc-товара лежат в 9 детях категории
  «Шпалери» и все же показываются на /oboi. Description разные (у shpaleri есть admin-copy).
- Исправление дешёвое: развести title/roles (см. §19, R5).

## 8. Technical Findings

1. **Карта рендеринга** (FACT): / и /oboi ISR 60s; /catalog/[slug] on-demand ISR 60s +
   generateStaticParams; PDP on-demand ISR 60s; filtered-близнецы force-dynamic через proxy
   rewrite (кэш ISR физически не может отдать чистый HTML на ?page/?sort — проверено тестами);
   статик-инфо-страницы. Рендеринг-парити: весь SEO-контент (H1, цены, JSON-LD, описания,
   хлебные крошки) в стартовом HTML (server components; 'use client'-острова SSR-ят свои
   props).
2. **Canonical** (FACT): абсолютные через metadataBase; категории — path-форма; бренды —
   query-форма; noindex-страницы canonical НЕ эмитят (осознанная политика, тестами зафиксирована).
3. **Robots** (FACT): Disallow /admin, /api/, /checkout, /orders/, /cart, /favorites +
   meta-noindex на тех же сегментах (defense in depth). Нит: `/orders/` не покрывает голый
   /orders (сегодня 404 — неактуально).
4. **Редиректы** (FACT): legacy `/catalog?category=` → 308 path (GET-only); `/product/*_du`
   → 301 base (302 пары); trailingSlash default false, единообразно.
5. **localhost-fallback** (FACT): `NEXT_PUBLIC_SITE_URL ?? 'http://localhost:3000'` в 5 местах
   — при сбое env на деплое все каноникалы молча укажут на localhost. Нужен build-time guard.
6. **Info-страницы** (FACT): /about, /contacts, /delivery, /returns, /privacy, /terms — без
   собственного canonical и OG (мессенджер-превью показывает общую карточку магазина).
7. **Пагинация** (FACT): page>1 → noindex,follow; кламп 10 000; page-size 12; текущая страница
   — span, не ссылка; rel=prev/next отсутствуют (правильно, deprecated). Crawl-эксплозия
   ограничена (noindex + конечные комбинации), но каждый URL — force-dynamic рендер с
   Supabase-чтением: налог на crawl budget приемлем, мониторить.
8. **Мелочи**: устаревший комментарий «96% OOS» в merchant-feed.ts (реально 13%);
   устаревший комментарий next.config про «96 пар» (реально 302).

## 20. DO NOT CHANGE (выглядит подозрительно, но не трогать)

- **noindex-страницы без canonical** — осознанная политика (canonical на noindex посылает
  противоречивые сигналы). Не «чинить».
- **Пагинация noindex,follow** — валидный сценарий e-commerce; rel=prev/next не нужен
  (deprecated). Не индексировать page 2+.
- **Search-страницы noindex** — правильно; никакой индексации /catalog?q=.
- **Бренды в query-форме** — path-маршруты для брендов строить не нужно.
- **og:type website на PDP** — ограничение Next (триггерил бы ошибку эмиттера); продукт уже
  описан Product JSON-LD.
- **Отсутствие hreflang** — язык один, lang="uk" корректен.
- **Честность JSON-LD** — не добавлять выдуманные ratings/GTIN/priceValidUntil «для
  богатого сниппета».
- **ISR TTL 60s / sitemap 24h** — нормальные значения; не «оптимизировать».
- **CSP без nonce** — nonce-force динамического рендеринга убил бы ISR; SEO-нейтрально.
- **Attack Mode как код** — это дэшборд-настройка Vercel; в репо менять нечего.
- **Не создавать новые страницы под ключи** (блоги, brand-path, фильтр-лендинги) — текущего
  набора 5 112 URL достаточно; спрос не доказан.
- **Не трогать** checkout/payments/RLS/admin/stock-логику — вне SEO-scope, аудит их не
  касался (по брифу).
